F1 Critical

Tearsheet used without footer action buttons

Location
Issue & Why it matters
Fix
F1
● Tearsheet footer area
The Tearsheet — Wide component (node 2201:112765) has the footer wrapper hidden (hidden="true") with no primary/secondary action buttons rendered.
The Carbon for IBM Products Tearsheet pattern requires footer action buttons (at minimum a primary action and a Cancel/Close ghost button). The hidden footer wrapper means users have no keyboard-accessible way to confirm or dismiss the tearsheet — breaking the modal interaction pattern and creating an accessibility barrier.

The design shows the tearsheet is used as a full-screen data view with only an ✕ close button in the header, which is insufficient per Carbon tearsheet usage.

Carbon Tearsheet usage →
Add a visible footer with at minimum a Cancel ghost button to the Tearsheet.
import { Tearsheet } from '@carbon/ibm-products'; <Tearsheet title="Published endpoints (4)" actions={[ { kind: 'ghost', label: 'Close', onClick: handleClose, } ]} > {/* table content */} </Tearsheet> // Remove hidden footer wrapper

F4 Major

Contextual layer token used instead of semantic $layer-01

Location
Issue & Why it matters
Fix
F4
● Table background + toolbar
Variable definitions show layer (contextual): #f4f4f4 and field (contextual): #f4f4f4 — both using contextual aliases rather than the explicit semantic tokens $layer-01 and $field-01.
Carbon v11 uses contextual tokens (e.g. layer) that automatically adapt across nesting levels. Using the raw contextual alias without a defined layer context can cause unexpected colour inheritance when the component is nested inside another layered container — for example inside a Tearsheet which already establishes a layer context.

The correct tokens for a table toolbar background are $layer-01 (white) for the DataTable surface, and $layer-accent-01 for toolbar hover states.

Carbon colour tokens →
Use explicit semantic Carbon layer tokens in SCSS instead of contextual aliases.
// Instead of contextual alias: background: var(--cds-layer); // Use explicit semantic token: background: var(--cds-layer-01); // For toolbar hover: background: var(--cds-layer-accent-01); // For field inputs: background: var(--cds-field-01);
F5 Minor

Table content left padding is 32px — deviates from Carbon $spacing-05 (16px)

Location
Issue & Why it matters
Fix
F5
● DataTable toolbar & header row
The toolbar wrapper (node 2201:112786) starts at x=32 and the header row (node 2201:112788) also starts at x=32. Variable definitions confirm Cell specs/Left padding: 16 — but actual offset from the tearsheet content edge is doubled at 32px.
The variable definition shows the cell left padding should be $spacing-05 (16px), which aligns with Carbon's DataTable default. However, the table wrapper inside the Tearsheet content area adds an additional 32px offset, creating 32px total left padding on the toolbar — twice the Carbon standard.

This is a layout inconsistency that creates visual imbalance inside the Tearsheet — the table appears indented rather than spanning edge-to-edge within the content zone.

Remove the extra 32px wrapper offset — let the DataTable span full width inside the Tearsheet content zone.
// Remove additional left margin on wrapper .tearsheet-content .data-table-wrapper { margin-left: 0; padding-left: 0; } // Carbon DataTable handles its own // internal 16px cell padding via // $spacing-05 automatically
F6 Minor

Tooltip on Tryout button uses custom dark popover — not Carbon Tooltip

Location
Issue & Why it matters
Fix
F6
● Row 4 Tryout button hover
Node 2201:113577 is named Tooltip body item and appears as a dark-background custom popover showing "Available for APIs only" — positioned at x=1233, y=422. Code Connect maps it to Tooltip but without a standard Carbon Tooltip snippet.
The "Available for APIs only" message appears as a custom dark tooltip overlay rather than using Carbon's standard Tooltip component. Carbon's Tooltip ensures consistent positioning, keyboard dismissal (Escape), focus management, and ARIA role="tooltip" associations.

A custom popover risks inconsistent z-index stacking inside the Tearsheet and does not guarantee ARIA tooltip association with the trigger button.

Carbon Tooltip usage →
Wrap the disabled Tryout button in a Carbon Tooltip to explain why it is disabled.
import { Tooltip, Button } from '@carbon/react'; import { Send } from '@carbon/icons-react'; <Tooltip label="Available for APIs only" align="bottom" > <Button kind="ghost" size="xs" hasIconOnly iconDescription="Try out endpoint" renderIcon={Send} disabled /> </Tooltip> // Remove custom Tooltip body item layer
