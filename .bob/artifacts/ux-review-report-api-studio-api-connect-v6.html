Summary

Screen 1: IBM API Studio — Test detail, GET/petId  ·  Screen 2: IBM API Connect — API Manager, Paths & Operations detail.

Both inputs are live dev builds from related IBM API management products. 13 findings identified. The most significant are structural Carbon violations shared across both products — custom tree navigation and inconsistent tab variants — creating a cross-product consistency problem for every user navigating between the two tools.

⚠ Image-inferred. All findings are based on visual inspection — no Figma URL or Code Connect data was provided. Token-level violations cannot be confirmed from screenshots alone. One false positive was corrected this session: F1 (Create new assertion button) was confirmed as Carbon Tertiary via the Figma panel.

Carbon Compliance
F2 Left navigation tree — custom implementation in both products Critical image-inferred
Location
Issue & Why it matters
Fix
F2
● Both screens
Screen 1 — entire left tree panel (APIs, Policy sequences, Tests, Environment, Assertion hierarchy)

Screen 2 — same structure, different custom implementation with ⊕ add icons and chevron expand targets
Two different custom tree navigation implementations across two related products. Neither uses Carbon's TreeView component. API Studio uses custom caret icons with a blue left-border selected state. API Connect uses a separate custom pattern.

Carbon's TreeView handles keyboard navigation, expand/collapse, and selected state automatically via $layer-selected-01. Two visually different navigation systems for identical content structures increase maintenance cost and confuse users moving between products.

Carbon TreeView usage →
Replace both custom trees with Carbon TreeView. Remove all custom border/background CSS — $layer-selected-01 is applied automatically.
import { TreeView, TreeNode } from '@carbon/react'; <TreeView label="Explorer"> <TreeNode id="apis" label="APIs" isExpanded> <TreeNode id="api1" label="API 1" /> </TreeNode> <TreeNode id="tests" label="Tests" isExpanded> <TreeNode id="name" label="Test name" selected /> </TreeNode> </TreeView> // Remove custom active state: // .nav-item--active { // border-left: 3px solid #0f62fe; // }
F3 Tabs — two different Carbon variants across the same product suite Critical image-inferred
Location
Issue & Why it matters
Fix
F3
● Both screens
Screen 1 — tab bar: Parameters / Body / Assertions (line variant)

Screen 2 — top: API Spec / Policy / API Set (contained) + nested below: Gen info / Paths & Ops (line) — two tab bars on one screen
API Studio uses line tabs. API Connect uses contained tabs at the top and nests a second set of line tabs below — two tab bars on one screen.

Carbon specifies one Tab variant per product context. Mixing line and contained falsely signals different navigation hierarchies. Carbon does not support nested tab bars.

Carbon Tabs usage →
Align both products to line tabs. Remove contained variant from API Connect. Consolidate the two tab levels on Screen 2 into one.
import { Tabs, TabList, Tab, TabPanels, TabPanel } from '@carbon/react'; <Tabs> <TabList aria-label="API sections"> <Tab>Parameters</Tab> <Tab>Body</Tab> <Tab>Assertions</Tab> </TabList> <TabPanels> <TabPanel>...</TabPanel> </TabPanels> </Tabs> // Remove: <Tabs type="contained">

● Screen 1
Right content panel — wide dropdown field directly below the tab bar
Bottom-border-only styling — no box border, no label above the field. Matches neither Carbon Dropdown nor Carbon Select. Placeholder text is acting as a label substitute.

Placeholder text disappears on selection, leaving the field permanently unlabelled. The custom border style breaks under theme changes and lacks Carbon's built-in keyboard accessibility.

import { Dropdown } from '@carbon/react'; <Dropdown id="assertion-ref" titleText="Refer to existing assertion" label="Select assertion..." items={assertionItems} itemToString={ (item) => (item ? item.label : '') } />
F5 Breadcrumb — current page item is a link on both screens Major image-inferred
Location
Issue & Why it matters
Fix
F5
● Both screens
Screen 1 — "Test 1 / GET/petId" — last item as blue link

Screen 2 — "Projects / jacobson_goldner…" — last item as blue link
Current page item in both breadcrumbs is rendered as a clickable blue link — identical to parent items. Carbon requires the current page to be non-interactive using isCurrentPage with no href.

A clickable current-page item navigates nowhere or reloads the page. Screen readers rely on the semantic distinction to announce the user's current location correctly.

Carbon Breadcrumb usage →
Add isCurrentPage to the last BreadcrumbItem and remove its href. Apply to both products.
import { Breadcrumb, BreadcrumbItem } from '@carbon/react'; <Breadcrumb> <BreadcrumbItem href="/tests"> Test 1 </BreadcrumbItem> <BreadcrumbItem isCurrentPage> GET/petId </BreadcrumbItem> </Breadcrumb>

A solid #0f62fe left border is used as the selected indicator. Carbon's TreeView selected state uses $layer-selected-01 as a full-row background fill — not a border.

Screen 1 — near-black, consistent with Carbon Gray 100 (#161616)

Fix
F10
● Both screens
Screen 1 — "GET/petId" ~28–32px, semibold

Screen 2 — "jacobson_goldner_soap_api" ~22–24px, regular weight
Two equivalent page-level titles rendered at noticeably different sizes and weights across related products.

Page title mismatches make the UI feel unfinished and increase cognitive load for users switching between tools. Carbon's $productive-heading-04 (28px, semibold) is the correct token for page-level titles in productive UIs.
Align both products' page titles to productive-heading-04.
// Before — mismatched // S1: font-size 30px; weight 600 // S2: font-size 22px; weight 400 // After — both products @use '@carbon/react/scss/type' as *; .page-title { @include type-style( 'productive-heading-04' ); }

F12 Icon-only action buttons missing accessible names — both screens Major image-inferred
Location
Issue & Why it matters
Fix
F12
● Both screens
Screen 1 — assertion header: ✏ edit + 🔗 link icons

Screen 2 — API title row: ✏ edit + 🗑 delete icons
Four icon-only buttons have no iconDescription prop. Their purpose is not announced to screen readers or displayed on hover.

Carbon requires hasIconOnly and iconDescription on all icon-only Buttons. These render as an aria-label and a visible tooltip — without them keyboard and screen reader users cannot determine what the button does.

Carbon Button accessibility →
Add hasIconOnly and iconDescription to every icon-only Button across both screens.
import { Button } from '@carbon/react'; import { Edit, TrashCan } from '@carbon/icons-react'; <Button kind="ghost" hasIconOnly renderIcon={Edit} iconDescription="Edit assertion" tooltipAlignment="center" /> <Button kind="ghost" hasIconOnly renderIcon={TrashCan} iconDescription="Delete API" tooltipAlignment="center" />

F13
● Screen 1
Content area — ⓘ icon immediately after the "Use custom endpoint" toggle label
The toggle label placement is correct per Carbon. The ⓘ tooltip trigger has no aria-label — its purpose cannot be announced to a screen reader.

F14
● Screen 1
Assertions DataTable — only the populated state visible. Screen 2's "No parameters found" empty state with pictogram is the correct model.
No empty state, skeleton loading, or error state designed for the assertions table. Without these, developers build ad-hoc solutions that diverge from Carbon's built-in patterns.

API Connect already gets this right. Replicating it in API Studio costs minimal effort and ensures a consistent experience across both products.
Design and annotate empty and loading states. Use API Connect's "No parameters found" pattern as the model.
import { DataTableSkeleton } from '@carbon/react'; // Loading state {isLoading && ( <DataTableSkeleton columnCount={4} rowCount={3} /> )} // Empty state {!isLoading && rows.length === 0 && ( <p>No assertions found. Create one to get started.</p> )}
