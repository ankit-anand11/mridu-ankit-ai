Summary

Screen 1 — Replicas tab: Runtime detail view showing a data table of container replicas with status and icon-only action buttons.   Screen 2 — Security tab: Pairing tokens table and Credentials card with password inputs and Regenerate buttons.

The Figma design uses Carbon Design System components throughout — IWHI navigation shell, Carbon DataTable, Carbon Tabs, Carbon PasswordInput, and Carbon Buttons are all correctly named in the layer tree and use correct Carbon tokens (Text/text-primary, Layer/layer-01, Border/border-subtle-01, Button/button-tertiary, IBM Plex Sans throughout).

Two critical accessibility gaps exist: icon-only action buttons in both tables have no accessible name annotation in the design. Five major issues span row height mismatch between Figma (64px pairing-token rows) and dev (~48px), a non-Carbon key icon on the Generate button, a tooltip component that is statically positioned in the layout rather than triggered on hover/focus, and a confirmed icon mismatch on the Sync button — the dev implementation uses a different icon shape than the one specified in the Figma design. One additional finding (◆ Unknown badge) was previously rejected and is tracked in Accepted UI Gaps.

⚠ Token validation note. All findings are grounded in Figma MCP data (get_variable_defs + get_metadata + get_design_context) and confirmed against Carbon MCP docs. Token assignments in the Figma file are correct. The gaps identified are structural/pattern-level, not token-level violations.
