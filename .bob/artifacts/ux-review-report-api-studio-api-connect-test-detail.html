Summary

Two screenshots analysed: IBM API Studio — Test detail screen (design) and IBM API Connect — API Manager path detail screen (dev implementation). Both appear to be live dev builds rather than a Figma design vs dev pair — noted below. Input is screenshot-only; all findings are image-inferred (no Figma URL or Code Connect data). Carbon MCP token verification was not available in this session — findings reference Carbon v11 standards from published guidelines.

The two screens are from related but distinct products — API Studio and API Connect. The comparison reveals meaningful cross-product visual inconsistency in navigation patterns, tab components, button hierarchy, and typography treatment. These are flagged as Major findings.

Carbon Compliance Findings
F1 — "Create new assertion +" button: non-Carbon ghost/outline button pattern
● Critical
In API Studio, the "Create new assertion +" button uses a custom outlined blue button style (blue border, blue text, white fill). This does not match any Carbon Button variant. The correct Carbon variant for a secondary additive action alongside a primary field is Tertiary or Ghost — not a custom-bordered style. The "+" icon should be a Carbon icon rendered via Add from @carbon/icons-react, placed as renderIcon prop.
Carbon standard: Button usage — carbondesignsystem.com/components/button/usage
image-inferred
▸ Carbon fix
Replace the custom outlined button with a Carbon Tertiary or Ghost Button with the Add icon.
// Before (custom style) <button class="custom-outline-btn">Create new assertion +</button> // After import { Button } from '@carbon/react'; import { Add } from '@carbon/icons-react'; <Button kind="tertiary" renderIcon={Add}> Create new assertion </Button>
F2 — Left navigation tree: missing Carbon TreeView or SideNav — custom implementation detected
● Critical
Both screens show a left-panel tree navigator (APIs, Policy sequences, Tests, Environment, Assertion hierarchy). In API Studio the tree items have no visible expand/collapse affordance consistent with Carbon's TreeView pattern — caret icons are custom SVGs, indentation is inconsistent, and the active item highlight (solid blue-left bar) does not match Carbon's TreeNode selected state which uses $layer-selected-01 as a background, not a left border. API Connect uses a different treatment entirely (chevrons as separate clickable targets, + icons for add actions inline with tree labels) — a different custom implementation.
Carbon standard: Tree view usage — carbondesignsystem.com/components/tree-view/usage
image-inferred
▸ Carbon fix
Replace the custom tree with Carbon's TreeView component. Selected state should use the built-in selected prop, not a custom border.
// After import { TreeView, TreeNode } from '@carbon/react'; <TreeView label="Explorer"> <TreeNode id="apis" label="APIs"> <TreeNode id="api1" label="API 1" /> </TreeNode> <TreeNode id="tests" label="Tests" isExpanded> <TreeNode id="test-name" label="Test name" selected /> </TreeNode> </TreeView>
F3 — Cross-product inconsistency: two different Tab implementations for the same pattern
● Critical
API Studio uses a line-tab pattern (underline on active tab, no background) with tab labels: Parameters, Body, Header, Authorization, Variables, Assertions, Conditions. API Connect uses a filled/contained tab pattern (solid background on active tab: API Specification, Policy, API Set) AND a second set of tabs below it (General information, Security, Paths and Operations, Components, Documentation) using the line pattern. These are two different visual treatments of the same Carbon Tab component across the same product suite. Carbon's Tabs component must be used consistently — one style per product context.
Carbon standard: Tabs usage — carbondesignsystem.com/components/tabs/usage
image-inferred
▸ Carbon fix
Align both products to the same Tabs variant. For a product UI (not a content site), the line variant is the Carbon default. Do not mix contained and line within the same product suite.
// Consistent usage across both products import { Tabs, TabList, Tab, TabPanels, TabPanel } from '@carbon/react'; <Tabs> <TabList aria-label="API detail sections"> <Tab>Parameters</Tab> <Tab>Body</Tab> <Tab>Assertions</Tab> </TabList> <TabPanels> <TabPanel>...</TabPanel> </TabPanels> </Tabs>
F4 — "Refer to existing assertion" dropdown: non-Carbon Select/ComboBox pattern
● Major
The "Refer to existing assertion" dropdown in API Studio has a flat bottom border only (no box border), which matches neither Carbon Dropdown (full border box) nor Carbon Select. The placeholder text sits left-aligned inside with no label above — Carbon requires a visible titleText label above all Dropdown instances.
Carbon standard: Dropdown usage — carbondesignsystem.com/components/dropdown/usage
image-inferred
▸ Carbon fix
Replace with Carbon Dropdown and add a visible titleText label.
// After import { Dropdown } from '@carbon/react'; <Dropdown id="assertion-ref" titleText="Refer to existing assertion" label="Select assertion..." items={assertionItems} itemToString={(item) => (item ? item.label : '')} />
F5 — Breadcrumb: active/current page item is not distinguished from parent links
● Major
In API Studio, the breadcrumb reads "Test 1 / GET/petId". "GET/petId" is the current page — it should not be a link and should be rendered with isCurrentPage prop (no href). Currently it appears visually identical to "Test 1" (same blue link colour). Carbon's Breadcrumb pattern requires the current page item to be non-interactive and visually distinct.
Carbon standard: Breadcrumb usage — carbondesignsystem.com/components/breadcrumb/usage
image-inferred
▸ Carbon fix
Add isCurrentPage to the last BreadcrumbItem and remove its href.
// After import { Breadcrumb, BreadcrumbItem } from '@carbon/react'; <Breadcrumb> <BreadcrumbItem href="/tests">Test 1</BreadcrumbItem> <BreadcrumbItem isCurrentPage>GET/petId</BreadcrumbItem> </Breadcrumb>
F6 — API Connect: "Get Started" floating overlay — not a Carbon pattern
● Major
A "Get Started" panel is visible in the bottom-right of the API Connect screen with an ✕ close button. This is a custom floating element — not a Carbon Notification, Popover, or Tooltip. Carbon has no "floating onboarding card" pattern; the closest sanctioned pattern would be an inline notification or a guided tour using Carbon's coachmark pattern from IBM Products. The custom implementation has no visible focus trap, no role annotation, and no keyboard-dismissal affordance visible.
Carbon standard: Notification usage — carbondesignsystem.com/components/notification/usage
image-inferred
▸ Carbon fix
Replace with a Carbon ActionableNotification or, for onboarding, the Coachmark from @carbon/ibm-products.
// Option A — inline notification import { ActionableNotification } from '@carbon/react'; <ActionableNotification kind="info" title="Get started" subtitle="Explore the API Manager features." actionButtonLabel="Learn more" onClose={() => setVisible(false)} /> // Option B — IBM Products Coachmark (onboarding) import { Coachmark } from '@carbon/ibm-products';
Token & Spacing Findings
F7 — Active nav item: custom blue left-border instead of $layer-selected-01 background
● Major
API Studio's selected tree/nav item ("Test name", "GET/petID") uses a solid blue #0f62fe left border as the selected indicator. Carbon's TreeView and SideNav selected state uses $layer-selected-01 as a background fill across the full row width, not a border. The left blue bar is a custom pattern that breaks the Carbon selected-state token contract.
Carbon token: $layer-selected-01 — background of selected interactive layer items
image-inferred
▸ Carbon fix
Remove the custom left-border selected indicator. Use Carbon's built-in selected state which applies $layer-selected-01 automatically.
// Before (custom SCSS) .nav-item--active { border-left: 3px solid #0f62fe; } // After — use Carbon TreeNode selected prop <TreeNode id="test-name" label="Test name" selected /> // Carbon applies $layer-selected-01 automatically — no custom CSS needed
F8 — Top header bar: custom black (#161616 or #000000) background instead of Carbon Shell token
● Major
Both screens use a near-black top header. API Studio header appears to be #161616 (Carbon Gray 100 — correct for the Gray 100 theme shell). API Connect header appears lighter — closer to #1a1a1a or a custom dark value — creating a visible inconsistency between the two products. The correct token for the Carbon shell header background is $background-inverse in Gray 100 theme or $shell-header-bg-01. Both products must use the same theme token.
Carbon token: $background-inverse / $shell-header-bg-01
image-inferred
▸ Carbon fix
Align both product headers to the same Carbon Gray 100 shell theme token. Do not hardcode background colours.
// Before .header { background: #1a1a1a; } // After (SCSS) @use '@carbon/react/scss/theme' as *; .header { background: $background-inverse; }
F9 — API Connect: "Path parameters" section heading spacing appears larger than $spacing-05
● Minor
The vertical gap between the "Path parameters" section heading and the table below it appears to be approximately 24–28px — consistent with $spacing-06 (24px). However, the gap above the section heading (from the textarea above) appears closer to 40px, which would be $spacing-08. Without Figma metadata this cannot be confirmed precisely, but the spacing rhythm appears inconsistent within the same screen.
Carbon spacing scale: $spacing-06 = 24px · $spacing-07 = 32px · $spacing-08 = 40px
image-inferred
▸ Carbon fix
Audit section-to-section vertical spacing and align to a consistent spacing token — either $spacing-06 or $spacing-07 throughout, not a mix.
// Consistent vertical rhythm (SCSS) .section + .section { margin-top: $spacing-07; } // 32px .section__heading { margin-bottom: $spacing-05; } // 16px
Typography Findings
F10 — Page title typography inconsistent between products
● Major
API Studio renders the page title "GET/petId" at approximately 28–32px, bold — consistent with Carbon's $productive-heading-04 (28px, semibold) or $productive-heading-05 (32px). API Connect renders "jacobson_goldner_soap_api" at approximately 24px — closer to $productive-heading-03. Two products serving the same user role (API developer) use visibly different heading sizes for equivalent page-level titles. Both should use the same type token.
Carbon type token: $productive-heading-04 — 28px / semibold / recommended for page-level titles in productive UIs
image-inferred
▸ Carbon fix
Align both product page titles to $productive-heading-04.
// Before — inconsistent sizes /* API Studio */ .page-title { font-size: 30px; font-weight: 600; } /* API Connect */ .page-title { font-size: 24px; font-weight: 400; } // After (SCSS) — both products @use '@carbon/react/scss/type' as *; .page-title { @include type-style('productive-heading-04'); }

● Minor
The DataTable column headers (Name, Key, Action, Value in API Studio; Name, Located in, Ref name in API Connect) appear to use a medium font weight rather than the semibold that Carbon's DataTable header style specifies ($label-01 token: 12px, 400 weight for column labels OR $productive-heading-01: 14px, 600 weight depending on table density).
Carbon token: DataTable header uses $productive-heading-01 (14px, 600 weight)
image-inferred
▸ Carbon fix
Ensure the DataTable component's header row uses $productive-heading-01 — do not override font-weight on table headers.
// Do not override Carbon DataTable header typography // If overridden in custom CSS, remove: .bx--table-header-label { font-weight: 400; } // ← remove this // Use Carbon DataTable directly — it applies correct tokens automatically import { DataTable, Table, TableHead, TableRow, TableHeader, TableBody, TableCell } from '@carbon/react';
Accessibility Flags (Carbon pattern level)
F12 — Edit and link icons in assertion header: icon-only buttons with no visible accessible name
● Major
The assertion section header in API Studio shows two icon-only action buttons (pencil/edit icon and a link/chain icon) with no visible label. Carbon requires all icon-only interactive controls to have an iconDescription prop (renders as aria-label). Without this, screen readers cannot announce the button's purpose. Same pattern appears in API Connect's edit (pencil) and delete (trash) icons next to the API title.
Carbon a11y pattern: all icon-only Buttons must include iconDescription — carbondesignsystem.com/components/button/accessibility
image-inferred
▸ Carbon fix
Add iconDescription (and hasIconOnly) to every icon-only Button.
// Before — missing accessible name <Button kind="ghost"><EditIcon /></Button> // After import { Button } from '@carbon/react'; import { Edit, TrashCan } from '@carbon/icons-react'; <Button kind="ghost" hasIconOnly renderIcon={Edit} iconDescription="Edit assertion" tooltipAlignment="center" /> <Button kind="ghost" hasIconOnly renderIcon={TrashCan} iconDescription="Delete assertion" tooltipAlignment="center" />
F13 — "Use custom endpoint" Toggle: label placement follows Carbon pattern but tooltip icon needs accessible name
● Minor
The Toggle + label "Use custom endpoint" pattern in API Studio is structurally correct — label is visible and placed correctly to the right of the toggle. However, there is a ⓘ tooltip icon immediately after the label with no visible accessible name annotation. Carbon's Tooltip trigger (when used as an icon button) requires iconDescription for the trigger icon, typically "More information" or a context-specific description.
Carbon a11y pattern: Tooltip triggers must have an accessible name
image-inferred
▸ Carbon fix
Add iconDescription to the Tooltip trigger icon.
// After import { Toggle, Tooltip } from '@carbon/react'; import { Information } from '@carbon/icons-react'; <Toggle labelText="Use custom endpoint" id="custom-endpoint" /> <Tooltip description="Custom endpoint allows you to override the default API base URL."> <button type="button" className="tooltip-trigger"> <Information aria-label="More information about custom endpoint" /> </button> </Tooltip>

Note: Mechanical WCAG checks (contrast ratios, tab order, screen reader announcement) are out of scope for this review. Use IBM Equal Access Checker for those.

Handoff Completeness
F14 — No empty state, loading state, or error state visible for the assertions table
● Minor
The assertions DataTable in API Studio shows data rows but no indication of how the table behaves when: empty (no assertions created yet), loading (async fetch in progress), or in an error state (fetch failed). Carbon's DataTable pattern includes built-in empty state and skeleton loading row variants. If these states are not designed, developers will create ad-hoc solutions.
Carbon pattern: DataTable empty state — carbondesignsystem.com/components/data-table/usage/#empty-state
image-inferred
▸ Carbon fix
Design and annotate the empty, loading, and error states for the DataTable. Use Carbon's TableToolbarContent for empty state messaging and DataTableSkeleton for loading.
// Loading state import { DataTableSkeleton } from '@carbon/react'; {isLoading && <DataTableSkeleton columnCount={4} rowCount={3} />} // Empty state (no rows) {!isLoading && rows.length === 0 && ( <p className="empty-state">No assertions added yet.</p> )}
