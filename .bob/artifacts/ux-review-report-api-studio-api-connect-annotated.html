Carbon Compliance Findings
F1 — "Create new assertion +" — custom outlined button, not a Carbon variant image-inferred
● Critical
Screen 1 — API Studio
Right panel · middle
"Create new assertion +" — blue border, blue text, white fill. Not a Carbon Button kind. The + icon is a text character, not a Carbon icon.
Carbon Button has four kinds: primary, secondary, tertiary, ghost, danger. No variant uses a custom blue border with white fill. For an additive secondary action next to a field, Tertiary is correct. The icon must be Add from @carbon/icons-react passed via renderIcon.
Carbon standard: carbondesignsystem.com/components/button/usage
▸ Carbon fix
Replace the custom outlined button with Carbon Tertiary Button and Add icon.
// Before — custom style <button class="outline-btn">Create new assertion +</button> // After import { Button } from '@carbon/react'; import { Add } from '@carbon/icons-react'; <Button kind="tertiary" renderIcon={Add}> Create new assertion </Button>
F2 — Left navigation tree: custom implementation in both products — Carbon TreeView not used image-inferred
● Critical
Both screens
Screen 1 · left panel
Custom caret icons, inconsistent indentation, active item uses blue left-border (not Carbon selected state)
Screen 2 · left panel
Different custom implementation — chevron expand targets, inline ⊕ add buttons, different icon sizes. Two separate non-Carbon patterns for the same navigation type.
Carbon's TreeView component handles expand/collapse, keyboard navigation, and selected state ($layer-selected-01 background). Neither screen uses it. Two different custom implementations for the same navigation pattern across related products is a critical consistency violation.
Carbon standard: carbondesignsystem.com/components/tree-view/usage
▸ Carbon fix
Replace both custom trees with Carbon TreeView. Selected state is handled automatically — remove any custom border CSS.
// After — both products import { TreeView, TreeNode } from '@carbon/react'; <TreeView label="Explorer"> <TreeNode id="apis" label="APIs" isExpanded> <TreeNode id="api1" label="API 1" /> </TreeNode> <TreeNode id="tests" label="Tests" isExpanded> <TreeNode id="test-name" label="Test name" selected /> </TreeNode> </TreeView> // Remove any custom active state CSS: // .nav-item--active { border-left: 3px solid #0f62fe; } ← delete
F3 — Tabs: two different Carbon variants used across the same product suite image-inferred
● Critical
Both screens
Screen 1 · content area
Line tabs — underline on active, transparent background. Parameters / Body / Header / Assertions…
Screen 2 · top of content
Contained tabs — filled/bordered background on active. API Specification / Policy / API Set
Screen 2 · nested below
Line tabs again — General information / Security / Paths and Operations… A second tab bar nested under the contained tabs.
Carbon Tabs has two variants: line (default, for productive UIs) and contained (for higher-density, navigational contexts). Using both within the same product suite — and nesting them on the same screen — breaks the Carbon usage guideline that says tabs should be used consistently within a product context.
Carbon standard: carbondesignsystem.com/components/tabs/usage
▸ Carbon fix
Align both products to line tabs. Remove the contained variant from API Connect's top-level navigation. Do not nest two tab bars on the same screen.
// Consistent across both products import { Tabs, TabList, Tab, TabPanels, TabPanel } from '@carbon/react'; <Tabs> <TabList aria-label="API detail sections"> <Tab>Parameters</Tab> <Tab>Body</Tab> <Tab>Assertions</Tab> </TabList> <TabPanels> <TabPanel>...</TabPanel> </TabPanels> </Tabs> // Remove: <Tabs type="contained"> — not appropriate here
F4 — "Refer to existing assertion" dropdown: bottom-border only, no visible label above image-inferred
● Major
Screen 1 — API Studio
Right panel · below tabs
Wide dropdown with flat bottom border only, placeholder text left-aligned, no label above the field. Not a Carbon Dropdown or Select.
Carbon Dropdown requires a visible titleText label above the field. A border-bottom-only treatment matches neither Carbon Dropdown (full box border) nor Select. The placeholder text is not a substitute for a label.
Carbon standard: carbondesignsystem.com/components/dropdown/usage
▸ Carbon fix
Replace with Carbon Dropdown. Add titleText as a visible label above the control.
// After import { Dropdown } from '@carbon/react'; <Dropdown id="assertion-ref" titleText="Refer to existing assertion" label="Select assertion..." items={assertionItems} itemToString={(item) => (item ? item.label : '')} />
F5 — Breadcrumb: current page item rendered as a link — Carbon requires isCurrentPage image-inferred
● Major
Both screens
Screen 1 · top of content
"Test 1 / GET/petId" — both items appear in blue link style. GET/petId is the current page and should be non-interactive.
Screen 2 · top of content
"Projects / jacobson_goldner…" — same issue. Last item is current page but styled as a link.
Carbon Breadcrumb's current-page item must use isCurrentPage prop (no href). This renders it as plain text — non-interactive and visually distinct from parent links.
Carbon standard: carbondesignsystem.com/components/breadcrumb/usage
▸ Carbon fix
Add isCurrentPage to the last BreadcrumbItem and remove its href.
// After — both products import { Breadcrumb, BreadcrumbItem } from '@carbon/react'; <Breadcrumb> <BreadcrumbItem href="/tests">Test 1</BreadcrumbItem> <BreadcrumbItem isCurrentPage> GET/petId </BreadcrumbItem> </Breadcrumb>

Token & Spacing Findings
F7 — Active nav item: custom blue left-border instead of $layer-selected-01 background image-inferred
● Major
Screen 1 — API Studio
Left nav · "Test name"
Selected item shows solid #0f62fe left border as indicator. Carbon uses $layer-selected-01 full-row background — not a border — for the selected/active state.
Outline · "GET/petID"
Same custom left-border selected treatment repeated in the Outline panel below the nav.
The $layer-selected-01 token fills the entire row width. A left-border-only approach is a custom token pattern that will break when the product theme changes.
Carbon token: $layer-selected-01 — background for selected interactive layer items
▸ Carbon fix
Remove custom border CSS. Use Carbon TreeNode's built-in selected prop — it applies $layer-selected-01 automatically.
// Before (custom SCSS) — remove this .nav-item--active { border-left: 3px solid #0f62fe; } // After — let Carbon handle it <TreeNode id="test-name" label="Test name" selected /> // $layer-selected-01 applied automatically, theme-safe
F8 — Header background: inconsistent dark values across products, possible hardcoded hex image-inferred
● Major
Both screens
Screen 1 · top bar
Near-black header — appears consistent with Carbon Gray 100 (#161616) shell token
Screen 2 · top bar
Visibly lighter dark — closer to #1a1a1a or a custom value. Inconsistent with Screen 1's header colour.
Both products must use the same Carbon shell header token: $background-inverse (Gray 100 theme) or $shell-header-bg-01. A visible difference between two products in the same suite suggests one or both are using hardcoded values.
Carbon token: $background-inverse / $shell-header-bg-01
▸ Carbon fix
Align both headers to the same Carbon shell token. Remove any hardcoded background values.
// Before .header { background: #1a1a1a; } // ← hardcoded, breaks themes // After (SCSS) @use '@carbon/react/scss/theme' as *; .header { background: $background-inverse; }
F9 — Section spacing rhythm inconsistent within API Connect screen image-inferred
● Minor
Screen 2 — API Connect
Content area · middle
Gap between Description textarea and "Path parameters" heading appears ~40px. Gap between heading and table below appears ~24px. Mixed spacing tokens on the same screen.
Spacing between sections should use a single consistent token. Mixing $spacing-08 (40px) above and $spacing-06 (24px) below creates an uneven vertical rhythm.
Carbon spacing scale: $spacing-06 24px · $spacing-07 32px · $spacing-08 40px
▸ Carbon fix
Pick one section-gap token and apply it consistently throughout the page.

Typography Findings
F10 — Page title size inconsistent across products: ~30px vs ~22px for equivalent headings image-inferred
● Major
Both screens
Screen 1 · h1 "GET/petId"
~28–32px, semibold — aligns with $productive-heading-04 or 05
Screen 2 · h1 "jacobson…"
~22–24px, regular weight — aligns with $productive-heading-03 or less. Noticeably smaller and lighter than Screen 1's title.
Both screens are page-level views for the same user role. They should use the same Carbon type token for the page title. $productive-heading-04 (28px, semibold) is recommended for productive UI page titles.
Carbon type token: $productive-heading-04 — 28px / semibold
▸ Carbon fix
Align both products' page titles to productive-heading-04.
// Before — mismatched /* Screen 1 */ .page-title { font-size: 30px; font-weight: 600; } /* Screen 2 */ .page-title { font-size: 22px; font-weight: 400; } // After — both products (SCSS) @use '@carbon/react/scss/type' as *; .page-title { @include type-style('productive-heading-04'); }

Accessibility Flags (Carbon pattern level)
F12 — Icon-only action buttons missing accessible names across both screens image-inferred
● Major
Both screens
Screen 1 · assertion header
Pencil (edit) icon button + chain/link icon button — no visible label, no tooltip on hover visible in screenshot
Screen 2 · API title row
Pencil (edit) icon button + trash (delete) icon button — same issue
Carbon requires all icon-only Buttons to include hasIconOnly and iconDescription. This renders as an aria-label and a tooltip on hover — without it, screen readers cannot announce the button's purpose.
Carbon a11y: carbondesignsystem.com/components/button/accessibility
▸ Carbon fix
Add hasIconOnly and iconDescription to every icon-only Button in both screens.
// Before — missing accessible name <Button kind="ghost"><EditIcon /></Button> // After import { Button } from '@carbon/react'; import { Edit, TrashCan, Link } from '@carbon/icons-react'; <Button kind="ghost" hasIconOnly renderIcon={Edit} iconDescription="Edit assertion" tooltipAlignment="center" /> <Button kind="ghost" hasIconOnly renderIcon={TrashCan} iconDescription="Delete API" tooltipAlignment="center" />
F13 — ⓘ tooltip icon next to "Use custom endpoint" has no accessible name image-inferred
● Minor
Screen 1 — API Studio
Content area · toggle row
Toggle labelled "Use custom endpoint" followed immediately by a small ⓘ icon. The icon is a tooltip trigger with no aria-label visible in the design.
The Toggle label and placement are correct per Carbon. The ⓘ tooltip trigger needs an accessible name so screen readers can announce it. "More information about custom endpoint" is the correct description.
Carbon a11y: tooltip triggers must have an accessible name
▸ Carbon fix
Add an aria-label to the ⓘ tooltip trigger button.
// After import { Toggle, Tooltip } from '@carbon/react'; import { Information } from '@carbon/icons-react'; <Toggle labelText="Use custom endpoint" id="custom-ep" /> <Tooltip description="Overrides the default API base URL."> <button type="button"> <Information aria-label="More information about custom endpoint" /> </button> </Tooltip>

Note: Mechanical WCAG checks (contrast ratios, tab order, screen reader output) are out of scope. Use IBM Equal Access Checker for those.

API Connect's empty state implementation ("No parameters found" with a pictogram) is a good model. API Studio's assertions table should have equivalent designs for empty, loading (skeleton), and error states before the next handoff.
