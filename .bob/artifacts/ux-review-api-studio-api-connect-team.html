F1 Critical image-inferred

Left navigation tree uses a custom component — Carbon TreeView exists

Location
Issue & Why it matters
Fix
F1
● Both screens · Left panel
API Connect (design) — Explorer tree with APIs, Policy sequences, Products, Plans, Tests, Environment, Assertion.

API Studio (implementation) — same tree pattern with different expand/collapse icons and ⊕ add controls.
Both screens use custom-built tree navigation. Carbon provides a TreeView component that handles expand/collapse, keyboard navigation (arrow keys), and selected state via $layer-selected-01 automatically.

Custom trees inherit full maintenance burden for accessibility (keyboard, screen reader) and theming. Using Carbon TreeView offloads this to the Carbon team.

Carbon TreeView usage →
Replace both custom tree panels with Carbon TreeView and TreeNode components.
import { TreeView, TreeNode } from '@carbon/react'; <TreeView label="Explorer"> <TreeNode id="apis" label="APIs" isExpanded> <TreeNode id="api1" label="jacobson_goldner_soap_api | 1" /> </TreeNode> <TreeNode id="tests" label="Tests" /> </TreeView> // Token: $layer-selected-01 for selected row // Remove all custom border/background CSS
F2 Critical image-inferred

Two primary buttons in one toolbar — violates single-primary-per-page rule

Location
Issue & Why it matters
Fix
F2
● API Connect · Top-right toolbar
"Create +" and "Stage or Publish" both appear as blue filled primary buttons in the same toolbar. Carbon allows only one primary button per screen outside of temporary flows.
Carbon states: "Each page should have only one primary button." Having two high-emphasis buttons confuses the hierarchy — users cannot tell which action is most important.

The Stage or Publish split button could remain primary (as the final publishing action). Create + should be downgraded to a secondary or ghost button.

Carbon Button usage →
Downgrade the "Create +" button to secondary kind. Keep "Stage or Publish" as the primary action.
import { Button } from '@carbon/react'; // "Create +" — downgrade to secondary <Button kind="secondary" renderIcon={Add}> Create </Button> // "Stage or Publish" — keep as primary split <ComboButton label="Stage or Publish" kind="primary"> ... </ComboButton>
F3 Critical image-inferred

Text area and text input have no visible label — placeholder text only

Location
Issue & Why it matters
Fix
F3
● API Connect · Main content area
Summary field — single text input showing only "Summary" as placeholder text with no external label above it.

Description (Optional) — text area showing only placeholder text, no visible persistent label.
Carbon's TextInput and TextArea guidelines state: "Label text is required unless you get an approved accessibility exemption." Placeholder text disappears as soon as the user begins typing, leaving screen reader users and users who have already typed content with no context for what the field requires.

The external label must be persistent above the field at all times.

Carbon TextInput usage →
Add a persistent labelText prop to both TextInput and TextArea. Do not rely on placeholder text as a label substitute.
import { TextInput, TextArea } from '@carbon/react'; <TextInput id="summary" labelText="Summary" placeholder="Summary" /> <TextArea id="description" labelText="Description" placeholder="Description (Optional)" helperText="Optional" /> // labelText renders as a persistent // visible label above the field
F4 Major image-inferred

Contained tabs used inside a component panel — Carbon requires line tabs inside components

Location
Issue & Why it matters
Fix
F4
● Both screens · Tab bars
API Connect — inner tab bar (General information / Security / Paths and Operations / Components / Documentation) appears to use contained-style tabs with a solid box outline, nested inside the main content panel.

API Studio — parameters tab bar (Parameters / Body / Header / Authorization / Variables / Assertions / Conditions) same pattern.
Carbon states: "When using line tabs within a component (like a modal), the first label should always align to the other content in the space. Do not use contained tabs." Contained tabs create a double-layering visual conflict inside content panels.

Line tabs are correct for nested use cases within components or panels.

Replace contained tabs inside panels with line tab variant. Remove the background box/container from the tab component.

F5 Major image-inferred

Form section background appears as a flat grey — likely $layer-02 used on $layer-01 context

Location
Issue & Why it matters
Fix
F5
● API Connect · Summary + Description fields
The Summary text input and Description text area both have a flat mid-grey background fill that differs from the white page background. This is image-inferred as a potential token misuse — the inputs may be using a hardcoded #f4f4f4 or an incorrect layer token rather than the correct Carbon TextInput field background.
Carbon TextInput fields in the default style use $field-01 as background (maps to #f4f4f4 in the white theme). If the surrounding page background is also #f4f4f4 the field appears to disappear or blend in — a sign the field is not on a $layer-01 surface, or the background is hardcoded instead of tokenised.

Ensure the page background uses $background and the field token correctly inherits $field-01.

Carbon TextInput usage →
Set the page container background to $background, not $layer-01, so TextInput $field-01 has contrast against it.
// Page wrapper .page-container { background: $background; // #ffffff } // TextInput uses $field-01 (#f4f4f4) // by default — do not override it // Confirm no hardcoded background // on the .cds--text-input class // Remove any custom: // background: #f4f4f4 or // background: var(--cds-layer)
F6 Major image-inferred

Add parameter button uses custom bordered style — should be Carbon ghost Button or ComboButton

Location
Issue & Why it matters
Fix
F6
● API Connect · Path parameters section
The "Add parameter ▾" button in the top-right of the path parameters table uses a custom outlined/bordered button style with a chevron — not a Carbon button variant. Carbon does not have an outlined-border button; the equivalent is a tertiary or ghost button paired with a chevron dropdown (ComboButton or MenuButton).
Carbon provides a ComboButton (or MenuButton) for exactly this pattern — a primary action with an attached chevron that opens a dropdown of additional options. Using a custom bordered button breaks the Carbon component boundary and creates a non-tokenised border.

Carbon Button usage →
Replace the custom outlined button with a Carbon ComboButton or ghost Button + chevron icon. Remove custom border CSS.
import { ComboButton, MenuItem } from '@carbon/react'; <ComboButton label="Add parameter" kind="ghost"> <MenuItem label="Path parameter" /> <MenuItem label="Query parameter" /> <MenuItem label="Header parameter" /> </ComboButton> // Removes need for custom // 1px border / chevron CSS
F7 Major image-inferred

Icon-only action buttons (edit, delete, refresh) have no visible accessible name annotation

Location
Issue & Why it matters
Fix
F7
● API Connect · Top-right page actions
The pencil (edit) and bin (delete) icon buttons next to "5 references" and "Update API spec" links have no visible label. In API Studio, the inline edit (✎) and unlink (⎆) icons on assertion rows are also icon-only with no accessible name annotation visible in the design.
Carbon's button guidelines state: "Regardless of how recognisable an icon may be, a tooltip is always required with text explaining what the icon button would do if clicked." Without an iconDescription prop, screen readers announce nothing meaningful for these buttons.

Carbon Button usage → Icon only buttons
Add iconDescription to every icon-only Button. This renders an accessible label and a tooltip on hover.
import { Button } from '@carbon/react'; import { Edit, TrashCan } from '@carbon/icons-react'; <Button kind="ghost" hasIconOnly renderIcon={Edit} iconDescription="Edit API" tooltipAlignment="end" /> <Button kind="ghost" hasIconOnly renderIcon={TrashCan} iconDescription="Delete API" tooltipAlignment="end" />
F8 Minor image-inferred

Top navigation bar height and icon density differs between design and implementation

Location
Issue & Why it matters
Fix
F8
● Both screens · Global header bar
API Connect (design) — header bar shows IBM API Connect wordmark + API Manager text link + Organization label + question mark + avatar. Height appears ~48px.

API Studio (implementation) — header shows IBM API Studio wordmark with fewer secondary links — no breadcrumb or org context visible. Height appears taller ~56px.

This is a Minor finding as it may reflect different products at different release states, but the drift should be tracked.

Confirm both products are using the Carbon UI Shell Header at its standard $spacing-09 (48px) height. Align secondary links and org context across products.

F9 Minor image-inferred

Toggle "Use custom endpoint" missing state text label in implementation

Location
Issue & Why it matters
Fix
F9
● API Studio · GET/petId detail panel
The Toggle component for "Use custom endpoint" shows only the label text to the right of the toggle switch. No state text ("On" / "Off") is visible beside the toggle switch itself — which Carbon's default Toggle requires.
Carbon's default Toggle requires state text (e.g. "On" / "Off") to be displayed adjacent to the toggle switch. Without state text, users relying on colour alone to understand toggle state may not perceive the current state. The small toggle variant is the only one where state text is optional.

The implementation appears to be using the default toggle size but omitting the labelA / labelB props.

Carbon Toggle usage →
Add labelA and labelB props to the Toggle to display On/Off state text, or switch to the small toggle variant where state text is optional.
import { Toggle } from '@carbon/react'; // Default toggle — state text required <Toggle id="custom-endpoint" labelText="Use custom endpoint" labelA="Off" labelB="On" toggled={useCustomEndpoint} onToggle={setUseCustomEndpoint} /> // OR use small variant (state text optional) // size="sm" removes state text requirement
