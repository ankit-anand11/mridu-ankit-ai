F1 Critical

Custom left navigation tree instead of Carbon TreeView

Location
Issue & Why it matters
Fix
F1
● Left Nav
Left Explorer navigation panel (APIs, Policy sequences, Tests, Environment hierarchy)
The left navigation panel uses custom tree items with hardcoded borders and non-standard caret expand icons. Carbon provides the native TreeView component which supports full keyboard accessibility (arrow keys navigation), aria-expanded attributes, and automated $layer-selected-01 background states.

Carbon TreeView usage →
Replace custom tree DOM with Carbon TreeView and TreeNode.
import { TreeView, TreeNode } from '@carbon/react'; <TreeView label="Explorer"> <TreeNode id="apis" label="APIs" isExpanded> <TreeNode id="api1" label="jacobson_goldner_soap_api" /> </TreeNode> </TreeView> // Remove custom border/active CSS
F2 Critical

Nested & mixed Tab variants across navigation levels

Location
Issue & Why it matters
Fix
F2
● Main Header Tabs
Top navigation tabs: API Specification / Policy / API Set + Nested tabs below (Paths & Operations)
The implementation mixes contained top tabs and nested line tabs on a single screen. Carbon Design System v11 guidance mandates a unified tab variant (standard line tabs) within a product context and discourages nested tab bars.

Carbon Tabs usage →
Consolidate to a single standard Carbon line Tabs component.
import { Tabs, TabList, Tab, TabPanels, TabPanel } from '@carbon/react'; <Tabs> <TabList aria-label="API Sections"> <Tab>API Specification</Tab> <Tab>Policy</Tab> <Tab>API Set</Tab> </TabList> </Tabs>
F3 Major

Breadcrumb active/current page item rendered as link

Location
Issue & Why it matters
Fix
F3
● Top Toolbar
Top breadcrumb bar (Projects / jacobson_goldner...)
The current page item in the breadcrumb is rendered as an active interactive link with color: #0f62fe. In Carbon, the current page breadcrumb item must be plain text with isCurrentPage={true} to prevent confusing circular navigation and meet accessibility standards.

Carbon Breadcrumb usage →
Set isCurrentPage on the terminal BreadcrumbItem.
import { Breadcrumb, BreadcrumbItem } from '@carbon/react'; <Breadcrumb> <BreadcrumbItem href="/projects">Projects</BreadcrumbItem> <BreadcrumbItem isCurrentPage>jacobson_goldner</BreadcrumbItem> </Breadcrumb>
F4 Major

Icon-only action buttons missing accessible labels

Location
Issue & Why it matters
Fix
F4
● Page Header Actions
Edit (pencil), Delete (trash), and info buttons next to title and table rows
Icon-only buttons lack visible text labels and missing iconDescription / hasIconOnly properties. Screen readers cannot announce the action purpose to assistive tech users.

Carbon Icon-Only Button usage →
Add hasIconOnly and descriptive iconDescription to all icon buttons.
import { Button } from '@carbon/react'; import { Edit, TrashCan } from '@carbon/icons-react'; <Button hasIconOnly renderIcon={Edit} iconDescription="Edit API name" kind="ghost" size="sm" />
F5 Major

Non-Carbon floating "Get Started" card in implementation

Location
Issue & Why it matters
Fix
F5
● Bottom Right
Floating "Get Started" black popover widget in the bottom-right corner
A custom dark floating card appears in the bottom-right viewport corner. Carbon does not include un-anchored floating cards outside standard Toast notifications, Tearsheets, or SidePanels. It causes content occlusion on smaller resolutions.

Carbon Patterns Overview →
Replace floating card with standard Carbon SidePanel or Toast Notification.
import { ToastNotification } from '@carbon/react'; <ToastNotification title="Get Started" subtitle="Follow the onboarding guide" caption="00:00" timeout={5000} />
