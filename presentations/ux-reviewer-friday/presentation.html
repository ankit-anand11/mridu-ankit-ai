02 / 15 The problem

IBM product teams have no way to continuously verify Carbon compliance

Invisible

Token violations hide in plain sight

A screen can look perfectly correct while the underlying code uses #0f62fe instead of $interactive-01. No visual check catches this.

Late

Issues surface after merge

Reviews are manual, ad hoc, and happen post-PR — or not at all. Teams have no gate. Non-compliant code ships silently with no accountability.

Expensive

Rework is the only remedy

A designer spent 2 hours annotating a single screen's issues, then waited 2 weeks for implementation. Then reviewed again. This repeats every sprint.

"If they are really using the Carbon component, are they really using the tokens? No one has any idea. So that gap is still there."

— Tech Lead, IBM API (webMethods)

09 / 15 MVP — what ships first

Phase 1 covers everything a team needs for pre-handoff and pre-PR reviews

Carbon compliance

Components

Custom components where a Carbon one exists. Wrong variants. Deprecated patterns. Names the exact Carbon alternative.

Token & spacing

Hardcoded values

Hex colours and px values where Carbon tokens should be used. Maps every violation to the correct token name.

Typography

Type system

Non-IBM Plex fonts. Sizes off the Carbon type scale. Hardcoded font-size values instead of type tokens.

Accessibility

Carbon patterns

Missing focus indicators. Icon buttons without labels. Form inputs without accessible names. Carbon pattern-level only — not WCAG mechanical checks.

Handoff completeness

Missing states

Interactive components without hover, focus, error, or disabled states designed. Caught before implementation starts.

Design-to-dev delta

Visual comparison

AI vision comparison of Figma design vs. dev screenshot. Flags drift with Carbon-aware interpretation — not just "it's different".

10 / 15 Output · what the report looks like

Every finding has a severity, a description, and an inline Carbon fix

🔴 Critical

Custom dropdown detected

Replace with <Dropdown> from @carbon/react. Token used: none — custom CSS border: 1px solid #8d8d8d. Carbon standard: use $border-subtle-01.

🔴 Critical

Interactive element unreachable by keyboard

Filter button has no visible focus ring. Carbon standard: all interactive elements must use $focus token on :focus-visible.

🟠 Major

Hardcoded spacing: 20px

Gap between cards is 20px. Should be $spacing-05 (16px). Theme-switch will break silently.

🟡 Minor

Table row hover — wrong token

Row hover uses #e8e8e8. Should be $layer-hover-01.

Design-to-implementation delta

3 discrepancies found vs dev screenshot Figma: Blue-60 primary button Dev: Blue-70 ← wrong token Figma: 48px header height Dev: 56px ← extra padding ($spacing-05 missing) Figma: Tag component (Carbon) Dev: Custom pill ← non-Carbon component

What Bob offers next

[A] Create Jira tickets for Critical findings
[B] Export report as downloadable HTML
[C] Show code fix for any finding
[D] Done for now

Phase 3 · Later

Pixel-precise CI comparison

Bob generates a Playwright script for the team's CI pipeline
Extracts computed CSS from live build

Collaborative dashboard for design/dev/QA

Status: Requires procurement. Evaluated separately.
